# Локальное хранилище и формат

`LocalFileStorage(absoluteRootPath)` принимает отдельную папку приложения. Под ней только `progress/<slot>/` и `preferences/<slot>/`. Slot — 1..64 ASCII lowercase букв/цифр, `_` и `-`, начинается буквой/цифрой; системные имена Windows отклоняются. Имя для UI хранится отдельно в DisplayName (до 512 UTF-8 bytes). Backend отвергает существующие symlink/reparse компоненты пути. От гонок со злонамеренным локальным процессом/сменой ссылок между проверкой и I/O этот backend не является защитой.

На каждый слот: `save.bin`, `backup.bin`, временный `pending-<guid>.bin`. `.easy-save.lock` в корне — постоянное имя файла с временно эксклюзивным OS handle; его наличие не означает занятую сессию. После падения процесса OS освобождает handle. Другой экземпляр/process получает Busy, не перезаписывает чужую операцию. Lock покрывает каждый filesystem вызов, включая чтение и перечисление. Сервис не держит файловую блокировку во время восстановления мира; приложение координирует несколько независимых SaveService, если они меняют один мир.

Запись: проверка входных bytes → новый pending → flush(true) → проверка прежнего primary → финальная проверка cancellation → File.Replace (существующий слот) либо File.Move (первый commit). Валидный предыдущий primary становится backup. Повреждённый primary не вытесняет последний корректный backup. Более новый неизвестный контейнер при перезаписи возвращает UnsupportedVersion и остаётся на диске. Платформы без File.Replace не получают небезопасную последовательность delete/move: операция завершается ошибкой.

При чтении NotFound/CorruptData основного файла можно прочитать backup (`RecoverBackup=true`). Primary не исправляется автоматически, а результат явно указывает RecoveredFromBackup. Неизвестная версия контейнера, участника или несовместимый мир не запускают fallback к старому сохранению. Pending никогда не считается committed и не восстанавливается автоматически. Остатки pending после аварии можно удалить при обслуживании собственной папки; во время штатной записи удаляется только собственный pending.

Удаление: директория выбранного слота атомарно переименовывается в `.deleted-<slot>-<guid>` внутри той же области. Это commit, сразу скрывающий primary и backup. Далее удаляются только известные файлы и пустая директория. Если cleanup не удался/внутри есть сторонний файл, Committed=true с предупреждением и путём остатка. Такие директории не перечисляются и не воскресают при чтении.

## Контейнер v1

Little-endian: 8 ASCII bytes `EASYSAVE`, Int32 version=1, Int32 body byte length, 32-byte SHA256 body. Далее body: Int32 scope, length-prefixed UTF-8 slot, display name, Int64 UTC ticks, Int32 count, entries (`key`, Int32 payload version, `payload`). Строки предваряются Int32 byte length. Нет type names/Type.GetType, BinaryFormatter, автоматического создания Unity-объектов или исполнения данных.

Проверяются magic, версия, длина, checksum, timestamp, scope/slot, размеры/число entries, уникальность keys, positive payload versions, строгий UTF-8 и отсутствие хвоста. Лимиты defaults: 16 MiB/file, 4 MiB/payload, 1024 participants/область; максимально настраиваемые 256 MiB и 65536 участников. Не делайте общий снимок таким большим без измерения кадров захвата/восстановления. Список локального backend ограничен 4096 слотами.

Checksum выявляет случайное повреждение, **не защищает от читов** и не является аутентификацией. Формат не шифрует данные. Кража прав локального пользователя/компрометация backend вне его границ. JSON payload проверяется его владельцем; ограничения контейнера не заменяют семантическую проверку механики.

## Платформы

Проверяемая первая платформа — Windows desktop/local NTFS. Не заявляется универсальная power-loss durability файловой системы/диска. Flush + atomic replace уменьшают окно повреждения, но не гарантируют поведение любого диска/сетевого share. WebGL явно отвергается; облако, консоли и SDK хранилищ — отдельные реализации ISaveStorage с тестами их commit/cancellation semantics. Mobile/macOS/Linux требуют своих smoke и crash/durability тестов перед выпуском.
