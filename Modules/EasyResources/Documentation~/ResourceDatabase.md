# Единая база ресурсов

Создайте **Create → EasyGameFramework → Resources → Resource Database**. В инспекторе введите имя и нажмите **Add**. Разверните запись: Name, Icon, Decimal Places, Unit, Weight и Volume редактируются здесь. Поле Search фильтрует по имени или стабильному ID. Все записи сохраняются внутри одного `.asset` базы, отдельных файлов ресурсов создавать не нужно. Undo/Redo поддерживают добавление, правку и удаление.

В Resource Container, составных стоимостях, лимитах и обычных полях Resource доступен поисковый выбор по базам. Он сохраняет прямую ссылку на запись. Поэтому BuildingCosts, InteractionTransfer и другие потребители используют ту же запись без обязательного глобального реестра или дополнительных runtime-поисков. Сама база не хранит деньги или состояние игры; живые количества остаются в ResourceStore.

У RewardProfile явно назначьте **Database**, затем выберите Resource из ограниченного списка этой базы и настройте Min/Max. Старые foreign/missing ссылки не заменяются автоматически: инспектор показывает их и объясняет ошибку. При смене точности ресурса нужно явно преобразовать уже настроенные количества/сохранения; редактор не угадывает такое преобразование.

```csharp
// savedDatabase — asset базы. Записи разрешаются один раз, прямые refs переиспользуются.
savedDatabase.TryGet(resourceId, out ResourceDefinition resource);
var price = new ResourceCost(new ResourceAmount(resource, 3));
wallet.TrySpend(price, out var failure);

var profile = ResourceRewardProfile.Create("Reward", savedDatabase,
    new ResourceRewardRange(resource, 3, 7));
var rolled = profile.Roll();
wallet.TryGrant(rolled, out failure);
```

`Resources` — read-only список, `Contains` проверяет точную ссылку, `TryGet` использует стабильный ID. Database реализует `IEnumerable<ResourceDefinition>` и подходит существующим Capture/Restore-каталогам: `store.RestoreState(state, savedDatabase)`. Во время обычной выдачи используются прямые ссылки, hot-path кошелька не ищет базы. Розыгрыш и атомарный TryGrant сохраняют прежние точные единицы, диапазоны и правила событий.

Для code-owned transient конфигурации и тестов есть `ResourceDefinition.Create(...)` и `ResourceDatabase.Create(name, params definitions)`. Такая база клонирует входной массив ссылок; жизненным циклом созданных объектов управляет вызывающий код. Это не способ создания каталога внешних persistent assets: сохранённая база должна владеть настоящими native subassets. `ResourceDatabaseEditorUtility.ValidateAsset` проверяет это правило, пропущенные/неперечисленные записи и ID. База не регистрируется в singleton.

## Удаление

**Remove** проверяет точные ссылки на запись в импортированных assets, prefabs, сохранённых сценах и открытых несохранённых объектах. Зависимость от файла базы сама по себе не блокирует удаление другого неиспользуемого ресурса в том же файле. Если запись используется или проверку нельзя закончить (например, зависимая сцена сохранена бинарно), операция отклоняется с путём и объяснением. Сначала замените/удалите ссылки либо используйте Undo; принудительной кнопки с потерей ссылок нет.

Проверка удаления — явная Editor-операция и может занять время в большом проекте. Она не запускается в Update и не открывает все сцены: сначала отбираются файлы по зависимости от базы; saved scene/prefab ссылки проверяются по GUID/localID в text serialization. Отдельно проверяются загруженные объекты. Внешние проекты/неимпортированные файлы/старые сохранения не могут быть найдены автоматически. Перед удалением записи со старыми save-данными решение принимает автор проекта. Прямой обход authoring-инструмента через низкоуровневый AssetDatabase — ответственность такого инструмента.

## Создание и перенос в Editor

```csharp
// Сначала создать и сохранить саму пустую ResourceDatabase через AssetDatabase.CreateAsset.
var coin = ResourceDatabaseEditorUtility.AddResource(database, "Coin");
// Для согласованного переноса существующего контента:
var remap = ResourceDatabaseEditorUtility.ImportDefinitions(database, oldResources);
```

`ImportDefinitions` проверяет весь список до копирования, создаёт вложенные записи с прежними `Definition.Id` и полями, возвращает `Dictionary<old,new>`. Исходники и внешние ссылки не изменяет. Вызывающий Editor-инструмент перепривязывает свою согласованную область контента, сохраняет и проверяет её после reload, затем удаляет старые resource-файлы. Повторный импорт тех же ID отклоняется. Это узкая операция authoring, без автопереноса всего проекта.

Несколько прежних GUID отдельных `.asset` нельзя сохранить внутри одного файла с одним GUID. `Definition.Id` остаётся стабильным для сохранений, но PPtr GUID/fileID меняется. Нельзя считать RemoveObjectFromAsset/AddObjectToAsset прозрачным переносом всех сериализованных ссылок. Канонические Samples~ вне импорта также требуют явного remap инструментом их владельца.

Новые базы/профили валидируются до RNG/выдачи. Во время Play параметры базы/профиля в инспекторе доступны только для чтения. Изменения runtime-контейнеров не переписывают определения.


## Большие базы

ValidateConfiguration строит локальный кеш ID и прямых ссылок за один проход. Повторные Contains/TryGet/валидация используют его без перебора всех записей; Roll после прогрева проверяет строки награды. Кеш принадлежит конкретной базе. Изменение дочернего SO через OnValidate, Undo, добавление/удаление, изменение списка и десериализация инвалидируют его. Собственный инструмент, меняющий конфигурацию в обход стандартной сериализации, вызывает InvalidateConfiguration(). Во время Play публичное API конфигурации доступно только для чтения. Первичная проверка/перестройка кеша выделяет память; прогретые lookup не должны её выделять.
