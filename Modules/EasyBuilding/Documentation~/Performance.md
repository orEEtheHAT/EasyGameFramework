# Производительность Building

Горячий Check использует переиспользуемые физические буферы, геометрию и пространственные запросы. У выбора/подтверждения, создания объектов и захвата/восстановления снимка другая стоимость: это не обещание нулевых аллокаций всех операций.

Регрессии WarmPreviewDoesNotAllocateManagedMemory и WarmSharedSessionLookupDoesNotAllocate содержат положительный контроль реальной аллокации и строгое требование 0 GC.Alloc событий нужного потока после прогрева. Глобальный GC Allocated In Frame выводится отдельно: он включает чужие фоновые потоки. Нет вычитания фона и повторов «до зелёного».

Запросы блокировки ввода хранятся по идентичности владельца. На чтении удаляются уничтоженные/неактивные Unity owners без аллокаций; обычный object-токен требует явного освобождения. До первого выбора и подтверждения не создаются глобальные менеджеры.

Для повторного измерения импортируйте Getting Started и выполните Tools > EasyGameFramework > Building > Create Benchmark Scene. Benchmark сохраняет fixture/число объектов, число запросов, режим spatial/linear, тайминги и GC positive control. Старые результаты отдельных пакетов не объявляются проверкой новой сборки. Runtime/Player результаты единого пакета оформляются после CUTOVER координатором.

Jobs/Burst здесь не добавлялись: текущий путь работает с Unity physics/objects на главном потоке. Новые массовые вычисления стоит переносить только после измерения конкретного узкого места.
