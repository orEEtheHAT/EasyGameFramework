# Физическое удержание

Новые Grab Action используют **Pose Mode → Authored Pose** по умолчанию. Начальные значения: Local Position = (0, 0, 0), Local Euler Angles = (0, 0, 0), Hold Distance = 2, Follow Speed = 0.5, Ignore Owner Collisions включён. Rigidbody остаётся динамическим. На FPS-игроке используйте существующий EasyMovement Interaction Motor с назначенным Character и Actor.PlayerRoot, указывающим на тело игрока. Дополнительный glue-код или специальный слой предметов не нужен.

```csharp
actor.HandAnchor = null; // camera fallback, если точка руки не нужна этой игре
grab.PoseMode = GrabPoseMode.AuthoredPose; // уже default нового компонента
grab.HoldDistance = 2;
grab.LocalPosition = Vector3.zero;
grab.LocalEulerAngles = Vector3.zero;
grab.FollowSpeed = .5f; // 0 — мягко, 1 — быстро.
grab.MovementLag = Vector3.zero; // убрать постоянное отставание от ходьбы.
// grab.IgnoreOwnerCollisions уже true по умолчанию.
```

Ожидаемый результат: root предмета стремится к точке в двух метрах перед View, его оси совпадают с View независимо от исходного поворота при взятии. После поворота взгляда предмет плавно догоняет целевую позу и прекращает вращаться. Стена продолжает останавливать Rigidbody; удержание не телепортирует предмет через препятствие. Сохраняются Rotate, Inspect, AdjustDistance, Throw, передача и несколько владельцев. [Как создать свой grab-префаб](../README.md#свой-grab-префаб).

В EasyGameFramework повторный основной Interact (E по умолчанию) отпускает собственный Grab независимо от движения мыши и текущего наведения. Для своего input reader используйте `actor.PressPrimary(out action, toggleInsteadOfHold)`; штатный адаптер EasyInput уже использует эту команду. Явные команды меню остаются адресными. [Маршрутизация ввода и matching Release](GrabReleaseInput.md).

## Точка и смещение

Приоритет всегда прежний: **Grab.HoldPoint → Actor.HandAnchor → Actor.View**. Явная точка HoldPoint или HandAnchor полностью заменяет вычисление расстояния перед камерой, включая inspection distance и AdjustDistance. Чтобы использовать Hold Distance, очистите обе ссылки.

В Authored Pose Local Position измеряется в метрах по локальным осям выбранной точки, без умножения на scale. Для View он прибавляется к `(0, 0, HoldDistance)`; ноль означает центр перед камерой. Для явного anchor он прибавляется к позиции самого anchor. В явном Preserve Pickup Pose ту же роль играет Hold Offset. GripPoint задаёт точку на предмете, которая следует к месту удержания; без него Authored использует root, а Preserve — центр массы. GripPoint должен принадлежать удерживаемому Rigidbody.

При выборе Preserve Pickup Pose параметр Rotation Mode → Stabilized сохраняет начальную ориентацию предмета относительно выбранной точки и затем следует её повороту. Free=0, KeepInitial=1, FollowView=2, Stabilized=3 сохраняют числовые значения. Для свободного вращения выберите Preserve Pickup Pose и Rotation Mode → Free: вращение остаётся свободным, пока его явно не контролируют Rotate, Inspect или второй участник. В Authored Pose Rotation Mode скрыт; работает авторская ориентация со Stabilized physics.

## Одинаковая поза при каждом взятии

На новом предмете **Pose Mode → Authored Pose** уже выбран; настройте **Local Position** и **Local Euler Angles**. Дополнительный компонент или Transform не требуется. Числовые значения enum остаются **Preserve Pickup Pose = 0**, **Authored Pose = 1**. Явно сохранённый режим существующих prefab/сцен не перезаписывается; Preserve сохраняет прежние Hold Offset, Rotation Mode, центр массы и ориентацию взятия. Переключение режима не переписывает эти настройки. Если поле режима ещё не было сериализовано, используется новый default Authored Pose.

```csharp
grab.PoseMode = GrabPoseMode.AuthoredPose;
grab.LocalPosition = new Vector3(.18f, -.12f, -.3f);
grab.LocalEulerAngles = new Vector3(10, 90, 0);
// Без anchors: root стремится к View + View.rotation * (.18, -.12, 1.7)
// при HoldDistance = 2. Ориентация root: View.rotation * Euler(10, 90, 0).
```

Обе величины используют один frame: **Grab.HoldPoint → Actor.HandAnchor → Actor.View**. Позиция измеряется в метрах, scale frame не применяется; для View по Z дополнительно прибавляется Hold Distance, изменяемое колесом, либо Inspection Distance при осмотре. Явные anchors заменяют distance и inspection positioning, как и в прежнем режиме. Local Euler Angles задаёт поворот **корня Rigidbody**, независимо от его исходной мировой ориентации. Масштаб самого предмета остаётся частью его геометрии.

Без GripPoint авторская позиция относится к **корню Rigidbody**, даже при смещённом centre of mass. При назначенном GripPoint к целевой позиции стремится **эта точка на предмете**; поворот по-прежнему задаётся для корня, локальный поворот GripPoint не учитывается. Например, ненулевой GripPoint сдвинет root так, чтобы точка хвата совпала с целью. GripPoint должен принадлежать удерживаемому Rigidbody. HoldPoint — внешняя цель, его нельзя помещать в иерархию самого удерживаемого предмета.

Authored Pose использует динамическую пружину с Follow Speed. Сохранённые Rotation Mode/Hold Offset применяются только в Preserve Pickup Pose; в Authored Pose их заменяют авторские поля. Перемещение идёт силами и моментом: Rigidbody остаётся динамическим, контакты с миром могут мешать достижению позы. Break Distance, owner collision exclusion и бросок работают как прежде. Временных HoldPoint GameObject и изменений anchors нет.

`Rotate` добавляет доворот **после** авторского поворота в локальных осях предмета. Осмотр сохраняет этот доворот и меняет distance только при View fallback. Передача другому Actor продолжает текущее удержание: manual rotation, inspection и выбранное расстояние сохраняются, а авторская поза вычисляется в frame получателя (явный общий HoldPoint имеет прежний приоритет). После полного отпускания следующий захват сбрасывает manual rotation/inspection/distance и снова достигает настроенной позы; сами авторские значения не меняются.

Существующий multi-owner хват сохраняется: позиция — среднее целей участников. При присоединении второго владельца авторская ориентация первого служит исходной позой; дальнейшее изменение оси между руками добавляет поворот к ней. Ручной доворот применяется один раз. При выходе одного участника оставшийся снова задаёт авторскую позу своим frame. Это общий хват одного Rigidbody, без отдельных IK-поз рук или второго GripPoint.

Для переноса проектного адаптера, который создавал временный HoldPoint, сначала выразите желаемую позу в постоянном frame (View/HandAnchor), включите Authored Pose и запишите Local Position/Local Euler Angles в prefab. При View fallback вычтите Hold Distance из локального Z. Если адаптер позиционировал GripPoint, сохраните ссылку; если он позиционировал root, очистите GripPoint. Затем уберите принадлежащий адаптеру временный HoldPoint и его запись в `grab.HoldPoint`, чтобы сработал нужный fallback. Постоянные внешние HoldPoint можно оставить. Данные конкретной игры и её миграция выполняются в игровом проекте.

## Два параметра отклика

**Follow Speed** (`0…1`, default `0.5`) управляет скоростью физического возвращения позиции и включённого поворота. `0` даёт мягкое медленное удержание, `1` — плотное быстрое. Это одна пружина с устойчивым демпфированием, без отдельного фильтра цели и дополнительных настроек времени, силы или частоты. Ноль не выключает удержание. Разницу удобно проверить: сместите цель либо поверните взгляд, затем остановитесь и сравните крайние значения.

**Movement Lag (XYZ)** (`0…1` по каждой оси, default `(0.5,0.5,0.5)`) задаёт физическое отставание при поступательном движении источника ходьбы. X — вбок, Y — вверх, Z — вперёд в локальных осях Movement Reference. `0` компенсирует выбранную постоянную скорость в демпфировании, `1` сохраняет отставание; `0.5` даёт промежуточный результат. `(0,0,0)` убирает устойчивый дрейф при ходьбе, `(1,1,0)` — только продольный. Новые компоненты и стандартный общий Playground начинают с `(0.5,0.5,0.5)`. Явно сохранённые значения потребителя остаются прежними.

Источник по умолчанию — Actor.PlayerRoot, когда он действительно несёт выбранный hold frame; для независимого внешнего HoldPoint используется сам frame. Advanced → Movement Reference позволяет задать реальный источник переноса и локальные оси нестандартного rig. Ссылка должна находиться вне удерживаемого Rigidbody. Неподвижная внешняя точка не получает скорость несвязанного игрока. Смена владельца, frame или reference сбрасывает историю; после телепорта rig и предмета вызовите `grab.ResetMotionTracking()`. Метод только сбрасывает измерение, не двигает тело.

Поворот камеры проходит через обычную динамическую пружину. Отдельных Camera Position/Rotation Lag, автоматической поддержки скорости/ускорения поворота и кинематического удержания нет. Rigidbody остаётся динамическим и сталкивается с миром. Контакт, разгон/торможение и конечный физический шаг могут задерживать движение; предмет не прикрепляется жёстко к камере.

## Настройка поворота

**Local Euler Angles** задаёт постоянную авторскую ориентацию root относительно HoldPoint → HandAnchor → View. **Follow Speed** меняет скорость прихода к ней вместе с позицией. В Preserve Pickup Pose режим Free оставляет вращение свободным, пока его явно не управляют Rotate, Inspect или второй участник.

Для ручного **R + мышь** у штатного адаптера игрока откройте **EasyInteraction Input → Advanced → Mouse Rotation Multiplier**. Это чувствительность ручного доворота, а не параметр удержания. `grab.Rotate(Vector2 degrees)` добавляет временный доворот; `AdjustDistance(delta)` и `SetInspection(bool)` сохраняют физический отклик. После полного отпускания ручная поза сбрасывается.

## Визуальная настройка позы

Выберите Grab Action в Authored Pose и нажмите **Edit Hold Pose in Scene View**. Временный **Preview Actor** либо **Preview View / Frame** задаёт рамку настройки: собственный HoldPoint имеет приоритет, затем Actor.HandAnchor, затем указанный preview frame/Actor.View. Без ссылок используется фиксированный снимок камеры Scene View; **Use Scene View as View** обновляет его. У View включено **Add Hold Distance**, у прямого anchor выключено. Ссылки preview живут только в Editor и не сохраняются на prefab.

Голубая wire-модель показывает целевую позу, включая Held Scale Multiplier и масштаб родителя/дочернего GripPoint. Реальный root не перемещается. **W** включает Position Handle, **E** Rotation Handle; **Frame Preview** наводит камеру, **Done** завершает настройку. Записываются только LocalPosition/LocalEulerAngles; Undo/Redo и обычный Save/Apply overrides сохраняют результат. В Prefab Mode можно работать с фиксированной камерой без ссылки на игровой Actor. Preview не моделирует препятствия или multi-owner hand-axis motion. Для skinned-модели Editor запекает текущую позу один раз; перезапустите preview после изменения позы/геометрии.

## Временный масштаб в руках

**Held Scale Multiplier** от0.1 до1 (default1) умножает исходный **localScale корня Rigidbody** на время общей сессии удержания. Модель, коллайдеры и GripPoint уменьшаются вместе; отдельный display-prefab не нужен. Исходный неравномерный scale и parent transform сохраняются. Значение применяется от захваченного snapshot, поэтому смена multiplier, второй владелец и transfer не накапливают умножения. Передача сохраняет уменьшенный размер; последний drop/throw/cancel, disable/death через Combat Guard, удаление GrabAction или pooling восстанавливают исходный размер.

Масса остаётся прежней. Automatic COM/inertia пересчитываются для геометрии; custom COM умножается на multiplier, custom inertia tensor на multiplier² с сохранением tensor rotation. После освобождения исходные значения и automatic flags восстановлены. Default1 не пишет scale/mass properties. Root масштабируется вместе с физикой; при расширении рядом со стеной могут возникнуть контакты, телепортаций или специальных правил пролезания через препятствия нет. Восстановление размера выполняется до освобождения owner collision exclusions, поэтому расширившийся внутри игрока предмет сохраняет защиту до разделения. Во время удержания исходный scale принадлежит GrabAction; не изменяйте его параллельно другим адаптером.

## Столкновения владельца

Ignore Owner Collisions включён по умолчанию. Исключаются только пары твёрдых коллайдеров данного Rigidbody и его владельца в PlayerRoot. Учитываются дочерние compound-коллайдеры; дочерние независимые Rigidbody не считаются частью предмета. Trigger-пары не меняются и не задерживают восстановление. Коллайдеры мира, collision layers и detectCollisions не отключаются.

EasyMovementInteractionMotor реализует `IInteractionCollisionFilter.AcquireCollisionExclusion(Rigidbody) : IDisposable`. Grab использует его автоматически. Адаптер добавляет OR-фильтр ECM2 для held Rigidbody: sweeps, overlaps и pushing не видят предмет. Прежний callback сохраняется; существующие ECM2 IgnoreCollision sets не изменяются. Независимые leases освобождают только свой запрос.

При drop/throw/cancel внутри владельца исключение остаётся до прекращения твёрдого пересечения. Проверяется физическая поза Rigidbody, включая дочерние коллайдеры, а не только интерполированный Transform. Внутренняя служба cleanup продолжает эту узкую работу после отключения или удаления GrabAction; она не двигает предмет. Пока два живых активных объекта действительно пересекаются, отсрочка намеренно сохраняется. После расхождения, отключения GameObject/коллайдеров или уничтожения участников запрос очищается; pooling и повторный захват создают своё владение. Для необычной пары, где ни один коллайдер не поддерживает ComputePenetration, используется консервативное пересечение bounds.

Исходное значение Physics.GetIgnoreCollision сохраняется до первого запроса. Несколько Grab-владельцев разделяют счётчик владения парой. Прямые внешние вызовы Physics.IgnoreCollision во время удержания не имеют owner/token и не могут быть надёжно отделены от нашего состояния: не меняйте те же пары этим способом до завершения удержания/отсрочки. Аналогично, прямая замена ECM2 colliderFilterCallback во время удержания может заменить наш фильтр; при освобождении чужой новый callback не перезаписывается. Для согласованного дополнительного исключения ECM2 используйте возвращаемую motor lease и Dispose.

Иерархии коллайдеров обновляются перед очередным физическим шагом; готовые compound-объекты учитываются сразу при захвате. Создание предметов, первое выделение списков и новые leases могут выделять память. Отсутствие GC проверяется отдельно для прогретого FixedUpdate и обслуживания существующих пар с калиброванным положительным контролем.
